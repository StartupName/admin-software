# Task Format

Tasks must be brief and clear, providing only the information necessary for the developer to begin working without ambiguity.

There is no need to repeat information already explained in the module documentation.

## Objective

A brief description of what needs to be developed and its purpose.

## Reference

An image or a link to the relevant section of the documentation.

## Location

The file or directory where the development work should take place.

## Requirements

A brief list of the features or behaviors the component must implement.

## Recommended Knowledge

Concepts the developer should be familiar with or research in order to complete the task.

## Acceptance Criteria

A verifiable list of the minimum conditions required to consider the task complete.

> [!NOTE]
> The developer may propose or implement additional improvements, provided they add value and do not negatively impact the project. Changes involving architecture, dependencies, or elements outside the task's scope may be included, provided they do not affect the system's overall functionality.
